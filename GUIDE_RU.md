# Руководство по использованию Replica в Google Antigravity 2.0

## 1. Введение: Что такое Replica?

**Replica** - это модульный набор из 12 навыков (skills) и 6 высокопроизводительных консольных утилит для среды Google Antigravity 2.0, предназначенный для чистого реверс-инжиниринга и воссоздания любых существующих приложений.

Оригинальный проект был создан Джейком Шинкариолом (Jake Schincariol) для Claude Code. Данный репозиторий представляет собой официальный нативный порт для **Google Antigravity 2.0**, разработанный **denb**. В порт добавлена поддержка кросс-платформенных приложений (веб, Windows Desktop, Android, CLI), написан мастер-оркестратор `replica-workflow`, а все скрипты оптимизированы для нулевого расхода лишней памяти и экономии токенов.

### Философия Clean-Room (Чистая комната)

Главный принцип Replica: **восстанавливается функциональность и пользовательский опыт (UX), но никогда не чужая интеллектуальная собственность**.

- **Никакого воровства кода**: Вы не декомпилируете и не копируете чужой закрытый исходный код. Код пишется с нуля на современном стеке на основе спецификации поведения.
- **Никаких чужих логотипов и брендов**: Приложение обязательно проходит ребрендинг с проверкой через автоматический сканер `sweep.py`.
- **Только легальные источники**: Изучаются только публичные страницы, официальная документация, скриншоты интерфейса и личный пользовательский аккаунт. Никакого парсинга за пейволлами или нарушения условий обслуживания сервисов.
- **Улучшение, а не просто клон**: Навык `replica-entrepreneur` анализирует реальные жалобы пользователей оригинального приложения из магазинов приложений и формирует список исправлений, делая ваш продукт лучше оригинала.

## 2. Архитектура пакета навыков

Пакет состоит из мастер-оркестратора, 11 специализированных навыков и 6 вспомогательных Python-утилит (работающих исключительно на стандартной библиотеке Python без `pip install`).

### Карта навыков

| Навык | Назначение |
|---|---|
| `replica-workflow` | **Мастер-оркестратор**: оценивает платформу, координирует этапы, отслеживает чекпоинты в `replica/state.md` и проверяет ворота качества (quality gates). |
| `replica-recon` | **Анализ и картирование**: составляет реестр экранов, карту пользовательских путей и матрицу возможностей `replica/features.csv`. |
| `replica-architect` | **Архитектура и БД**: проектирует структуру проекта, схему данных, правила доступа (RLS / SQLite) и API. |
| `replica-design` | **Дизайн-система**: извлекает дизайн-токены (цвета, шрифты, отступы), компоненты и проверяет контрастность по WCAG 2.2. |
| `replica-build` | **Разработка интерфейса**: собирает экраны по спецификации (каркас -> вертикальный срез -> все состояния). |
| `replica-backend` | **Серверная часть**: настраивает аутентификацию, базу данных, фоновые задачи, платежи и интеграции (если требуются). |
| `replica-test` | **Тестирование**: создает тестовый план и запускает автотесты (Playwright, FlaUI для Windows, Compose UI для Android). |
| `replica-diff` | **Оценка паритета**: сравнивает клон с оригиналом по структуре экранов (`imgdiff.py`) и матрице фич (`parity.py`). |
| `replica-entrepreneur` | **Анализ рынка и отзывов**: выявляет слабые места конкурента по реальным отзывам и формирует уникальное торговое предложение. |
| `replica-brand` | **Ребрендинг**: генерирует чистое имя, цветовую схему и проверяет кодовую базу сканером упоминаний бренда. |
| `replica-launch` | **Запуск и маркетинг**: готовит лендинг, ценообразование и проверяет карточку для App Store / Google Play. |
| `replica-deploy` | **Развертывание**: проводит предрелизную проверку (preflight gate) и формирует инструкцию по релизу. |

### Встроенные утилиты

Все утилиты запускаются из корня проекта через стандартный интерпретатор Python (`python`):

1. **`imgdiff.py`** (в `replica-diff`): Сравнивает два PNG-скриншота по расположению блоков и краям, игнорируя брендовые цвета. Потребляет всего ~23 МБ RAM.
2. **`parity.py`** (в `replica-diff`): Рассчитывает процент готовности функционала по `features.csv` и показывает недостающие фичи в порядке сборки.
3. **`contrast.py`** (в `replica-design`): Проверяет пары цветов токенов на соответствие стандарту доступности WCAG 2.2 (AA/AAA).
4. **`reviews.py`** (в `replica-entrepreneur`): Анализирует CSV-выгрузку отзывов, группирует их по темам (цена, баги, UX) и находит точные цитаты.
5. **`sweep.py`** (в `replica-brand`): Быстро ищет старые названия, домены и цвета оригинала в кодовой базе проекта, исключая бинарники и служебные папки компиляторов.
6. **`listing.py`** (в `replica-launch`): Проверяет заголовок, подзаголовок и описание карточки приложения на лимиты App Store и Google Play.

## 3. Установка и подключение в Google Antigravity 2.0

### Вариант 1: Глобальная установка (Рекомендуется)
Установив навыки глобально, они станут доступны агенту во всех ваших текущих и будущих проектах без дублирования файлов.

**Для Windows (PowerShell):**
```powershell
git clone https://github.com/denbdenb/replica-skill.git
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.gemini\config\skills"
Copy-Item -Recurse -Force replica-skill\.agents\skills\* "$env:USERPROFILE\.gemini\config\skills\"
```

**Для macOS / Linux (Bash):**
```bash
git clone https://github.com/denbdenb/replica-skill.git
mkdir -p ~/.gemini/config/skills
cp -r replica-skill/.agents/skills/* ~/.gemini/config/skills/
```

### Вариант 2: Локальная установка (В отдельный репозиторий)
Если вы хотите привязать навыки только к конкретному проекту:

```powershell
# В корне целевого проекта
New-Item -ItemType Directory -Force -Path ".agents\skills"
Copy-Item -Recurse -Force path\to\replica-skill\.agents\skills\* .agents\skills\
```

*Требования*: Установленный Python 3.8 или новее. Никаких сторонних библиотек ставить не требуется.

## 4. Режимы выполнения и работа с проектом

Replica поддерживает три режима сборки, управляемых оркестратором:

1. **Quick (Быстрый прототип / Интерфейс)**:
   - Этапы: Recon -> Architecture -> Design -> Build -> Diff.
   - Подходит для создания фронтенда, демо-версий или проверки UI-гипотез.
2. **Standard (Полноценный программный продукт)**:
   - Этапы: Quick + Backend + Test + Entrepreneur + Brand.
   - Подходит для локальных утилит, десктопных или мобильных приложений с собственной базой и тестами.
3. **Full (Полный коммерческий запуск)**:
   - Этапы: Standard + Launch + Deploy.
   - Подходит для SaaS, публикации в Google Play, App Store, Microsoft Store или деплоя на собственный домен.

### Чекпоинт проекта: `replica/state.md`

Все результаты работы сохраняются в папку `replica/` внутри вашего проекта. Оркестратор поддерживает актуальный файл `replica/state.md` размером 100-200 слов:
- Целевая платформа и выбранный стек технологий.
- Текущий этап и список завершенных этапов.
- Ключевые архитектурные решения.
- Статус ворот качества (пройдены ли тесты, чист ли бренд).
- Следующее действие и пути к артефактам.

Благодаря этому агент может возобновить работу в любой момент без повторного чтения сотен строк документации.

## 5. Пошаговое руководство: как работать в чате с агентом

### Шаг 0: Старт проекта

Вы можете запустить оркестратор одной фразой в диалоге с Antigravity:

> "Используй replica-workflow. Мы хотим разобрать приложение [Название] и создать наш аналог для [Web / Windows / Android]."

Агент автоматически:
1. Оценит платформу и особенности приложения.
2. Создаст директорию `replica/`.
3. Сформирует файл `replica/state.md`.
4. Перейдет к первому этапу.

---

### Шаг 1: Разведка и карта экранов (`replica-recon`)

**Что делает агент:**
Анализирует целевое приложение по предоставленным вами скриншотам, ссылкам на публичную документацию или описанию.
Формирует:
- `replica/recon.md`: опись всех экранов, иерархия блоков, переходы между экранами.
- `replica/features.csv`: структурированная таблица возможностей с приоритетами (must-have, nice-to-have).

**Пример запроса:**
> "Выполни этап replica-recon. Вот ссылка на документацию оригинального приложения и скриншоты главного экрана. Составь карту экранов и features.csv."

---

### Шаг 2: Выбор архитектуры и стека (`replica-architect`)

**Что делает агент:**
Подбирает оптимальный технологический стек под вашу задачу, проектирует схему базы данных и интерфейсы API. При этом учитывается тип приложения:
- **Для Web**: Next.js / SvelteKit / FastAPI + PostgreSQL (с правилами RLS).
- **Для Windows**: WinUI 3 (.NET 8 / C#) / WPF + локальный SQLite.
- **Для Android**: Kotlin + Jetpack Compose + Room (SQLite).
- **Для CLI**: Python / Go / Rust.

Формирует:
- `replica/architecture.md`: описание стека, структура каталогов, схема таблиц и эндпоинты.

---

### Шаг 3: Дизайн-система и токены (`replica-design`)

**Что делает агент:**
Создает дизайн-систему: цветовую палитру, типографику, сетку отступов и спецификации базовых компонентов в `replica/design/tokens.json`.

**Проверка контраста (Quality Gate):**
Агент запускает встроенный анализатор контрастности:
```bash
python .agents/skills/replica-design/contrast.py replica/design/tokens.json --summary
```
Если контраст не дотягивает до стандарта доступности WCAG 2.2 AA (4.5:1 для обычного текста), агент автоматически корректирует цвета до получения успешного статуса.

---

### Шаг 4: Разработка интерфейса (`replica-build`)

**Что делает агент:**
Поэтапно реализует пользовательский интерфейс в соответствии с картой экранов:
1. Каркас навигации (Shell / Navigation Rail / Sidebar / TabBar).
2. Вертикальный срез ключевого экрана со всеми состояниями (загрузка, пустое состояние, отображение данных, ошибки валидации).
3. Остальные экраны по приоритету.

Прогресс фиксируется в `replica/build-log.md`.

---

### Шаг 5: Бэкенд и логика данных (`replica-backend`)

**Что делает агент (если применимо к платформе):**
- Подключает локальную или облачную базу данных, применяет миграции.
- Реализует аутентификацию и разграничение прав.
- Настраивает обработчики платежей (Stripe / LemonSqueezy / In-App Purchases).
- Создает безопасный файл конфигурации `.env.example`.

Результат описывается в `replica/backend.md`.

---

### Шаг 6: Тестирование (`replica-test`)

**Что делает агент:**
Создает `replica/test-plan.md` и пишет автотесты под целевую платформу:
- Веб: сквозные тесты на Playwright.
- Windows Desktop: UI Automation тесты на FlaUI или WinApp CLI.
- Android: инструментальные Compose UI тесты.

**Ворота качества**: Релиз не допускается при наличии критических открытых багов уровня S1/S2 в `replica/bugs.md`.

---

### Шаг 7: Оценка паритета и визуальный дифференциал (`replica-diff`)

**Что делает агент:**
Проверяет, насколько ваш клон соответствует задуманному оригиналу:

1. **Функциональный паритет:**
```bash
python .agents/skills/replica-diff/parity.py replica/features.csv --summary
```
Выводит процент готовности и проверяет реализацию обязательных фич (must-have).

2. **Визуальное сравнение верстки:**
```bash
python .agents/skills/replica-diff/imgdiff.py original.png clone.png --out replica/diffs/diff.png --summary
```
Алгоритм выявляет смещенные кнопки, неверные отступы и расхождения в структуре страницы, не отвлекаясь на смену темы или фирменного цвета.

---

### Шаг 8: Анализ отзывов и улучшение продукта (`replica-entrepreneur`)

**Что делает агент:**
Берет собранные отзывы пользователей оригинала из `replica/reviews.csv` и запускает анализ:
```bash
python .agents/skills/replica-entrepreneur/reviews.py replica/reviews.csv --out replica/feedback.md --summary
```
Утилита находит самые частые боли пользователей (например, "слишком дорого", "нет офлайн-режима", "сложный импорт данных"). Агент формирует документ `replica/fixes.md` со списком фич, которые выгодно отличают ваш клон от конкурента.

---

### Шаг 9: Ребрендинг и проверка чистоты (`replica-brand`)

**Что делает агент:**
1. Придумывает оригинальное имя, слоган и цветовую палитру для вашего продукта, сохраняя конфиг в `replica/brand.json`.
2. Запускает автоматическую проверку чистоты кодовой базы:
```bash
python .agents/skills/replica-brand/sweep.py . --avoid "ИмяКонкурента" --summary
```
Сканер проверяет все файлы проекта и гарантирует, что в коде не осталось упоминаний чужих брендов, доменов или оригинальных цветов.

---

### Шаг 10: Подготовка к запуску (`replica-launch`)

**Что делает агент:**
- Генерирует текст посадочной страницы (Landing page) с акцентом на преимущества перед оригиналом.
- Для мобильных и десктопных приложений формирует метаданные карточки стора (`replica/launch/listing.json`) и проверяет их линтером:
```bash
python .agents/skills/replica-launch/listing.py replica/launch/listing.json --summary
```
Линтер гарантирует, что названия и описания укладываются в ограничения App Store / Google Play и не содержат запрещенных слов.

---

### Шаг 11: Предрелизная проверка и публикация (`replica-deploy`)

**Что делает агент:**
Проверяет чек-лист `replica/deploy.md`:
- Все автотесты зеленые.
- Сканер бренда выдал 0 совпадений (`Clean sweep`).
- Контрастность цветов подтверждена.
- Обязательный паритет достигнут.

Запрашивает ваше прямое подтверждение и выводит команды сборки дистрибутива (Docker-образ, бинарный релиз, пакет MSIX для Windows или AAB для Android).

## 6. Особенности разработки под разные платформы

Replica не навязывает веб-технологии и умеет адаптироваться под любую платформу:

### Windows Desktop (WinUI 3 / WPF)
- Стек: C#, .NET 8/10, Windows App SDK, CommunityToolkit.Mvvm.
- Хранилище: Локальный SQLite или файлы JSON.
- Токены: `ResourceDictionary` в XAML (цвета и стили темы).
- Тестирование: FlaUI (UI Automation).
- Сборка: MSIX-пакет через WinApp CLI или автономный `.exe`.

### Android (APK)
- Стек: Kotlin, Jetpack Compose, Material 3, Gradle.
- Хранилище: Room (SQLite), DataStore.
- Токены: Compose Theme (`Color.kt`, `Type.kt`).
- Тестирование: Compose UI Test, эмулятор ADB.
- Сборка: Android App Bundle (`.aab`) или APK.

### Web SaaS
- Стек: Next.js / SvelteKit / Nuxt + TypeScript.
- Хранилище: PostgreSQL + Prisma/Drizzle.
- Токены: CSS Custom Properties / Tailwind Config.
- Тестирование: Playwright + axe-core.
- Сборка: Vercel / Docker / Node.js.

## 7. Советы по эффективной работе и экономии токенов

1. **Используйте флаг `--summary`**: Когда вы просите агента запустить любую утилиту из Replica, он получает краткий однострочный ответ вместо простыни текста, экономя до 90% токенов контекста.
2. **Опирайтесь на `replica/state.md`**: Если вы продолжаете работу в новом диалоге, просто напишите агенту:
   > "Прочитай replica/state.md и продолжай со следующего незавершенного этапа."
   Агенту не придется перечитывать все файлы проекта.
3. **Работайте с конкретными экранами**: На этапе `replica-build` просите агента собирать экраны по одному, сверяясь с ID экрана из `replica/recon.md`.
